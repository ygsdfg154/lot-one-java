# lot-one 项目 Go+Rust → Java 全量迁移方案

## 一、项目现状

| 维度 | 现状 |
|------|------|
| 项目类型 | IoT 物联网平台（设备定位/追踪/管理） |
| 后端语言 | Go（16.3万行）+ Rust（8.2万行）= 24.6万行 |
| 前端 | Vue3 + TypeScript（15.4万行，**保留不动**） |
| Go 服务1 | admin-console（Gin + GORM + Casbin，管理后台，~10万行） |
| Go 服务2 | device-app（Kratos + gRPC，设备App后端，~4.5万行） |
| Rust 服务 | iot-runtime（axum + tokio，设备网关/协议解析/数据写入，8.2万行） |
| 数据库 | MySQL（主库，70+表）+ Redis + MongoDB + TDengine（时序） |
| 消息队列 | Kafka |
| 对象存储 | 阿里云OSS / AWS S3 / 七牛 / 腾讯云COS / MinIO / 华为云OBS |
| 通信协议 | JT808（部标）+ HLXT（自定义）+ gRPC（服务间）+ HTTP（前端） |

## 二、迁移目标

1. **后端全量 Java 化**：Go + Rust 全部替换为 Java（Spring Boot 3 + Spring Cloud）
2. **前端零改动**：API 接口完全兼容，前端不需要修改一行代码
3. **数据库零迁移**：复用现有 MySQL/Redis/MongoDB/TDengine，表结构不变
4. **渐进式切换**：新旧系统并行运行，按模块灰度切换，可随时回滚
5. **性能不降级**：设备接入网关用 Netty 实现，协议解析用高性能二进制解析

## 五、API 兼容策略（前端零改动的核心）

### 5.1 管理后台（admin-console）API 兼容

原 GVA 框架的响应格式：
```json
{
  "code": 0,
  "data": { ... },
  "msg": "success"
}
```

Java 端必须**完全一致**：
- 成功：`code=0`，`data=业务数据`，`msg="success"`
- 失败：`code=7`（GVA默认错误码），`msg=错误信息`
- 分页：`data={ list: [...], total: 100, page: 1, pageSize: 10 }`

路由前缀保持不变：
- 原：`/api/base/login` → Java：`/admin/api/base/login`（网关去掉前缀后转发）
- 网关配置：`/admin/api/**` → 去掉 `/admin` 前缀 → admin-service

### 5.2 设备App（device-app）API 兼容

原 Kratos 同时提供 HTTP 和 gRPC：
- HTTP 接口路径保持不变（如 `/api/v1/user/login`）
- gRPC 接口：用 Spring Cloud OpenFeign 替代服务间调用，设备App只走HTTP
- 响应格式与原 Kratos 一致

### 5.3 网关路由配置（关键）

```yaml
# lot-one-gateway application.yml
spring:
  cloud:
    gateway:
      routes:
        - id: admin-route
          uri: lb://lot-one-admin
          predicates:
            - Path=/admin/api/**
          filters:
            - StripPrefix=1   # 去掉 /admin 前缀，保持原路径
        - id: device-route
          uri: lb://lot-one-device
          predicates:
            - Path=/device/api/**
          filters:
            - StripPrefix=1
        - id: query-route
          uri: lb://lot-one-query-api
          predicates:
            - Path=/query/api/**
          filters:
            - StripPrefix=1
```

前端只需把 baseURL 从 `http://old-host:port` 改成 `http://gateway:8080/admin`，其他零改动。

## 六、数据模型映射

### 6.1 MySQL 表（70+张，直接复用）

| 分类 | 表名前缀 | 数量 | Java 实体包 |
|------|---------|------|------------|
| 系统管理 | sys_ | 25+ | com.lotone.admin.entity.system |
| 业务核心 | lot_ | 30+ | com.lotone.admin.entity.lot |
| App用户 | lot_app_ / app_ | 15+ | com.lotone.device.entity |
| 示例 | exa_ | 5 | 可忽略或迁移 |

**映射规则**：
- Go struct 字段（蛇形列名）→ Java 实体（驼峰属性 + @TableField 注解）
- GORM 的 `gorm:"column:xxx"` → MyBatis-Plus 的 `@TableField("xxx")`
- GORM 的 `gorm:"primaryKey"` → `@TableId(type = IdType.AUTO)`
- 时间字段：`time.Time` → `LocalDateTime`
- JSON字段：`datatypes.JSON` → `String` + FastJSON 序列化，或 `@TableField(typeHandler = JacksonTypeHandler.class)`

### 6.2 Redis Key 设计（保持不变）

直接复用原 Go 代码中的 Redis Key 前缀和数据结构，确保新旧系统并行时缓存互通。

### 6.3 MongoDB 集合（保持不变）

设备实时数据、报警事件等存在 MongoDB，集合名和文档结构保持不变。

### 6.4 TDengine 超级表（保持不变）

时序数据（位置、轨迹）存在 TDengine，超级表结构和写入逻辑保持不变。

## 七、迁移阶段总览

| 阶段 | 周期 | 目标 | 产出 | 验收标准 |
|------|------|------|------|---------|
| **P0 准备** | 1周 | 环境搭建、骨架生成、代码生成器配置 | Java项目骨架、Nacos、开发环境 | 所有服务能启动、注册到Nacos |

| **P3 设备App** | 3周 | 迁移 device-app 后端（App用户/登录/支付/设备绑定） | App后端全量API | 设备App所有功能可用 |
| **P4 协议解析** | 3周 | 迁移 JT808 + HLXT 协议解析库 | lot-one-protocol jar | 协议编解码单元测试100%通过 |
| **P5 设备网关** | 3周 | 迁移设备接入网关（Netty TCP/UDP） | lot-one-iot-gateway | 设备能连接、注册、上报数据 |

**总周期：约 23 周（5-6个月）**，1人全职可完成；2人并行可压缩到 3-4 个月。
